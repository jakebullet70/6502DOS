CMDBASIC V1 Design Overview
Vision
CMDBASIC is intended to replace the traditional COMMAND.COM style shell with a command interpreter that feels natural to BASIC programmers while remaining small enough for an 8-bit machine.

Instead of DOS-style commands such as:

DIR
TYPE
ECHO
CD
CMDBASIC uses BASIC-oriented commands:

FILES
LIST
PRINT
CHDIR
The goals are:

Interactive command shell
Simple scripting language
Familiar BASIC syntax
Tiny memory footprint
Extensible through external commandlets
Identical behavior at the prompt and inside scripts
A user should be able to sit down at the prompt and immediately understand how to use the system.

Example:

PRINT "HELLO"
FILES
DATE
TIME
The shell command language and scripting language are the same language.

If something works at the prompt, it works in a script.

If something works in a script, it works at the prompt.

Architecture
CMDBASIC consists of three parts:

1. Built-In Commands
Core commands built directly into CMDBASIC.

Examples:

PRINT
INPUT
FILES
COPY
IF
GOTO
Built-in commands provide the foundation of the shell.

2. CMD Scripts
Text files interpreted by CMDBASIC.

Extension:

.CMD
Examples:

STARTUP.CMD
LOGIN.CMD
BACKUP.CMD
MENU.CMD
CMD files contain normal CMDBASIC source code.

Example:

MAIN:

CLS

PRINT "Main Menu"

INPUT A

IF A=1 FILES
IF A=2 END

GOTO MAIN
3. Commandlets
Small external utility binaries.

Extension:

.CBIN
Examples:

FREE.CBIN
EXIST.CBIN
WHICH.CBIN
MEM.CBIN
HELP.CBIN
Commandlets extend the shell without increasing the size of CMDBASIC itself.

Users do not need to know whether a command is built-in or implemented by a commandlet.

Examples:

FREE

MEM

EXIST CONFIG.SYS
CMDBASIC automatically locates and executes the appropriate commandlet.

Variables
Numeric Variables
A-Z
Example:

A = 10
B = 20
String Variables
A$-Z$
Example:

N$ = "STEVE"
Commandlet Parameter Slots
CMDBASIC provides a standard interface between scripts and commandlets.

The same slots are used for:

Passing arguments to commandlets
Returning values from commandlets
Numeric Slots
P1-P9
String Slots
P1$-P9$
This provides a fixed ABI while consuming very little memory.

Slot Clearing Rules
Before every commandlet execution CMDBASIC clears all slots.

Numeric slots:

P1-P9 = 0
String slots:

P1$-P9$ = ""
This guarantees deterministic behavior.

No commandlet may rely on values left behind by a previous commandlet.

Argument Passing
Arguments are loaded sequentially.

Example:

EXIST CONFIG.SYS SILENT
Commandlet receives:

P1$ = "CONFIG.SYS"
P2$ = "SILENT"
Unused slots remain cleared.

P3$-P9$ = ""
P1-P9 = 0
Return Values
Commandlets may modify any slot before returning.

Example:

FREE SILENT
Returns:

P1 = 15234
Script:

PRINT P1
Example:

EXIST CONFIG.SYS SILENT
Returns:

P1 = 1
Script:

IF P1=1
    PRINT "FOUND"
ENDIF
Recommended Slot Usage
Suggested convention:

P1      Primary numeric result

P1$     Primary string result

P2-P8   Additional results

P2$-P8$ Additional string results

P9      Error code
Success:

P9 = 0
Failure:

P9 <> 0
This is a convention rather than a requirement.

SETSYS
SETSYS displays or modifies shell environment variables.

Examples:

SETSYS PATH$="/COMMANDS;/SYSTEM"

SETSYS PROMPT$="X16>"

SETSYS EDITOR$="EDIT"
Display all system variables:

SETSYS
Example output:

PATH$=/COMMANDS;/SYSTEM
CURDIR$=/HOME
PROMPT$=X16>
EDITOR$=EDIT
User variables remain standard BASIC variables:

A=10
A$="STEVE"
SETSYS is reserved for shell and operating system configuration.

BIND
Creates command aliases.

Example:

BIND LS=FILES
Then:

LS
behaves as:

FILES
RUN
Transfers control to another executable.

Example:

RUN EDITOR
Example:

RUN SHELL
RUN exits the current script and launches the target program.

Commandlets
Commandlets are external commands stored on disk.

Examples:

FREE

MEM

EXIST CONFIG.SYS

WHICH EDITOR
From the user's perspective they behave exactly like built-in commands.

SILENT Mode
Many commandlets may choose to support a standard SILENT argument.

Normal:

FREE
Output:

Free Memory: 15234 bytes
Silent:

FREE SILENT

PRINT P1
Output:

15234
This allows commandlets to work both interactively and within scripts.

Example Startup Script
START:

CLS

PRINT "X16 UNIX"

FREE SILENT

PRINT "FREE MEMORY:"
PRINT P1

EXIST CONFIG.SYS SILENT

IF P1=0
    PRINT "CONFIG.SYS NOT FOUND"
    END
ENDIF

RUN SHELL

Design Philosophy
CMDBASIC is:

A replacement for COMMAND.COM
BASIC-inspired instead of DOS-inspired
Interactive and scriptable using the same language
Small enough for an 8-bit system
Extended through commandlets rather than shell bloat
Consistent between live use and scripts
The shell remains small and stable while new functionality is added through .CBIN commandlets and .CMD scripts.
